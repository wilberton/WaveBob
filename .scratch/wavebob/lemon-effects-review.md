# Lemon Studio effects: source review for WaveBob

Research note, 24 October 2026. This is design research, not implementation approval or final tickets. Instruments are excluded. Source snapshot: [`0af860dfd31c7ee9cbf8af6747617e031a1a7742`](https://github.com/ItsAlphaNeon/Lemon-Studio/tree/0af860dfd31c7ee9cbf8af6747617e031a1a7742). Public source files were downloaded to a temporary research folder and read; no upstream code was built, executed, installed or vendored into WaveBob. Sound quality and performance have not been measured here.

## Recommendation

Adoption update, 24 October 2026: the user approved all eleven effects, including
Balance, with the documented mode/routing limitations and egui editors. The
implementation approach is WaveBob-owned versions of the same algorithms using
upstream as reference, keeping the required parts rather than linking its DSP or
plugin crates in production. The approved [effects contract](effects-and-clip-controls.md)
and tickets 27–44 supersede the rollout/scope suggestions below; source findings
remain a record of the reviewed upstream revision.

Use the effect DSP implementations as the starting point for built-in effects, with WaveBob-owned typed parameter state, rendering adapters and egui control windows. Preserve the useful layout and interactions of the Lemon editors while recreating their drawing in egui. Do not adopt the whole plugin-hosting framework merely to reach the DSP: the wrappers already delegate to `os_engine::effects`; `os-engine` itself has no NIH-plug dependency, whereas the plugin/editor crates introduce NIH-plug, native window code, `os-ui`, `os-theme` and host-link plumbing. Reuse therefore has a plausible clean boundary, although extracting the relevant modules and their helper dependencies still needs an implementation review. [DSP interface and inventory](https://github.com/ItsAlphaNeon/Lemon-Studio/blob/0af860dfd31c7ee9cbf8af6747617e031a1a7742/crates/os-engine/src/effects/mod.rs), [engine manifest](https://github.com/ItsAlphaNeon/Lemon-Studio/blob/0af860dfd31c7ee9cbf8af6747617e031a1a7742/crates/os-engine/Cargo.toml), [example wrapper manifest](https://github.com/ItsAlphaNeon/Lemon-Studio/blob/0af860dfd31c7ee9cbf8af6747617e031a1a7742/plugins/lemon-reverb/Cargo.toml).

The requested pre-alpha scope needs no existing-project migration, legacy state conversion or FL Studio project compatibility. Use WaveBob's own versioned effect IDs and parameter schemas. Compatibility machinery in the source is evidence of how parameters map to sound, not a requirement to reproduce those binary formats.

### Proposed rollout boundary

Start by proving the shared chain/parameter/window contract with Soft Clipper and Reverb, then add the standard Parametric EQ mode and Fast Distortion. Soft Clipper is a small control/transfer-curve case; Reverb exercises tails, stereo output and a realistic separate editor immediately. Add Delay, Chorus, Limiter, Stereo Enhancer, Stereo Shaper and Transient Processor after the shared realtime, latency, reset and bounce behavior is established. This is a proposed delivery order rather than a request to drop the eventual ten-effect catalog. Balance can remain optional because it overlaps existing gain/pan controls and has a less familiar folding balance law.

For the initial EQ editor, provide the seven bands, shapes and usual graph controls; enable advanced linear-phase/quality modes only after callback-safe kernel preparation and dynamic latency compensation are implemented. Limiter can initially use its internal detector, with external sidechain unavailable. Stereo Shaper can provide its main stereo matrix/delay/phase controls while omitting difference-output routing. These choices avoid presenting controls whose required engine support is absent; the underlying limitations and sources are described below.

For tempo without a beat grid, proposed policy: default to free milliseconds/Hz in the waveform UI, and show an explicit project `Effect tempo` setting in BPM only when tempo sync is enabled. Use that same numeric BPM in waveform audition, arrangement playback and offline/headless/MCP rendering. The effect must not infer tempo from selection duration or the waveform ruler. A waveform document carried into an arrangement should retain the same project effect tempo; changing it invalidates affected cached bounces. `120 BPM` would match the upstream wrappers' initialization fallback, but WaveBob should make the fallback visible rather than silently treating it as detected tempo. This policy is a WaveBob proposal; source support consists of `set_tempo` and the wrappers' explicit 120 BPM initialization, cited in issue 6 below.

## Separate egui control windows

These editors are custom-painted `os-ui::Canvas` views with explicit hit regions and platform-specific embedded child-window adapters. They are not egui widgets that can simply be mounted inside WaveBob. The painting, parameter binding and window/input code should be treated separately. [Reverb view](https://github.com/ItsAlphaNeon/Lemon-Studio/blob/0af860dfd31c7ee9cbf8af6747617e031a1a7742/plugins/lemon-reverb/src/view.rs), [Reverb editor](https://github.com/ItsAlphaNeon/Lemon-Studio/blob/0af860dfd31c7ee9cbf8af6747617e031a1a7742/plugins/lemon-reverb/src/editor.rs), [shared native-window dependencies](https://github.com/ItsAlphaNeon/Lemon-Studio/blob/0af860dfd31c7ee9cbf8af6747617e031a1a7742/crates/os-plugkit/Cargo.toml).

Proposed WaveBob behavior:

- A compact ordered stack row holds bypass, effect name, an open-controls button, reorder grip and an overflow menu. No parameter expansion or Apply button in the panel.
- Open controls in a real independent native window. Reopening an already open instance focuses it. Keep one window per effect instance; multiple different instances can be open together.
- Window titles identify owner and instance, e.g. `Reverb · voice.wav · 03`. Changing selection must not silently retarget an open editor. Removing its effect or closing its owner closes/inactivates the corresponding window; closing a control window does not bypass sound.
- Reproduce each effect's group layout, graph behavior, meaningful value scales, reset and precise numeric entry. Use WaveBob typography/colors and a consistent title/preset/bypass strip. Preserve the Lemon controls' functional organization rather than branding the whole app like Lemon Studio.
- Support DPI scaling, keyboard focus/transport shortcuts and lost/offscreen window recovery. Save window geometry as UI state, separately from sound state.
- Poll meter/analyzer data through bounded snapshots, and stop expensive visualization when a window is hidden. The existing EQ and limiter wrappers already gate analysis publishing on `editor_open`; this is a useful design precedent. [EQ wrapper](https://github.com/ItsAlphaNeon/Lemon-Studio/blob/0af860dfd31c7ee9cbf8af6747617e031a1a7742/plugins/lemon-parametric-eq-2/src/lib.rs), [limiter wrapper](https://github.com/ItsAlphaNeon/Lemon-Studio/blob/0af860dfd31c7ee9cbf8af6747617e031a1a7742/plugins/lemon-limiter/src/lib.rs).

The window behavior above is a proposal for WaveBob, not a claim that upstream implements independent egui windows.

## Issues to resolve before final tickets

1. **Realtime-safe changes need adaptation.** Reverb changes to room size recreate/clear tank lines. EQ linear-phase processing creates its `Lin` state and builds gain tables/FFT kernels on the processing path. Dynamics parameter changes resize lookahead/RMS storage and can increase smoother-chain storage. Direct calls are therefore not enough to guarantee allocation-free playback or uninterrupted tails. Prepare expensive replacement state outside the callback, preallocate bounded buffers, and specify crossfades/state transfer for topology changes. [Reverb `size_lines`/`set`](https://github.com/ItsAlphaNeon/Lemon-Studio/blob/0af860dfd31c7ee9cbf8af6747617e031a1a7742/crates/os-engine/src/effects/reverb.rs#L504), [EQ process and update path](https://github.com/ItsAlphaNeon/Lemon-Studio/blob/0af860dfd31c7ee9cbf8af6747617e031a1a7742/crates/os-engine/src/effects/eq/equalizer.rs), [kernel allocation](https://github.com/ItsAlphaNeon/Lemon-Studio/blob/0af860dfd31c7ee9cbf8af6747617e031a1a7742/crates/os-engine/src/effects/eq/lin.rs), [Dynamics work buffers](https://github.com/ItsAlphaNeon/Lemon-Studio/blob/0af860dfd31c7ee9cbf8af6747617e031a1a7742/crates/os-engine/src/effects/dynamics.rs).

2. **Smoothness differs by effect.** Reverb ramps levels, Delay smooths selected controls, while EQ documents next-block unsmoothed automation values. Do not promise every knob is click-free solely because it is live. Define effect-specific smoothing and topology transitions; compare the adapted sound against the pinned implementation. [Reverb ramp](https://github.com/ItsAlphaNeon/Lemon-Studio/blob/0af860dfd31c7ee9cbf8af6747617e031a1a7742/crates/os-engine/src/effects/reverb.rs#L426), [Delay smoothed settings](https://github.com/ItsAlphaNeon/Lemon-Studio/blob/0af860dfd31c7ee9cbf8af6747617e031a1a7742/crates/os-engine/src/effects/delay.rs#L95), [EQ automation](https://github.com/ItsAlphaNeon/Lemon-Studio/blob/0af860dfd31c7ee9cbf8af6747617e031a1a7742/crates/os-engine/src/effects/eq/equalizer.rs#L279).

3. **Latency compensation is required.** EQ modes and limiter lookahead report changing latency. Compensate parallel arrangement paths, align the playhead and exported/bounced audio, and make bypass/reorder transitions timing-safe. Removing processing delay from a rendered file is different from removing the intentional echo/reverb predelay. [EQ latency reporting](https://github.com/ItsAlphaNeon/Lemon-Studio/blob/0af860dfd31c7ee9cbf8af6747617e031a1a7742/plugins/lemon-parametric-eq-2/src/lib.rs#L191), [limiter latency reporting](https://github.com/ItsAlphaNeon/Lemon-Studio/blob/0af860dfd31c7ee9cbf8af6747617e031a1a7742/plugins/lemon-limiter/src/lib.rs#L183), [engine effect latency contract](https://github.com/ItsAlphaNeon/Lemon-Studio/blob/0af860dfd31c7ee9cbf8af6747617e031a1a7742/crates/os-engine/src/effects/mod.rs#L28).

4. **Tail rendering must terminate predictably.** Reverb and Delay wrappers return `KeepAlive`, not a finite tail duration; Delay permits feedback scaling up to 1.25. Silence-until-finished alone cannot guarantee a bounded bounce. Use a documented silence threshold/hold plus a maximum render duration and explicit handling of sustained feedback; report a capped tail. Keep later clips at their positions as already requested. Define whether per-effect bypass drains the old wet tail or cuts it via a short transition. [Reverb process](https://github.com/ItsAlphaNeon/Lemon-Studio/blob/0af860dfd31c7ee9cbf8af6747617e031a1a7742/plugins/lemon-reverb/src/lib.rs#L114), [Delay process](https://github.com/ItsAlphaNeon/Lemon-Studio/blob/0af860dfd31c7ee9cbf8af6747617e031a1a7742/plugins/lemon-delay/src/lib.rs#L114), [Delay feedback mapping](https://github.com/ItsAlphaNeon/Lemon-Studio/blob/0af860dfd31c7ee9cbf8af6747617e031a1a7742/crates/os-engine/src/effects/delay.rs#L761).

5. **Channel policy must be explicit.** The inspected effect wrappers expose stereo input/output only. A reasonable first version promotes mono input to dual mono for processing and keeps a stereo processed bounce when the chain generates stereo; exporting mono then requires an explicit downmix. Preserve the editable source channel count. Check phase/mono compatibility for stereo processors. This channel policy is a WaveBob proposal. [EQ layout](https://github.com/ItsAlphaNeon/Lemon-Studio/blob/0af860dfd31c7ee9cbf8af6747617e031a1a7742/plugins/lemon-parametric-eq-2/src/lib.rs#L154), [shared small-effect layout](https://github.com/ItsAlphaNeon/Lemon-Studio/blob/0af860dfd31c7ee9cbf8af6747617e031a1a7742/plugins/lemon-small-fx/src/lib.rs#L221), [Reverb layout](https://github.com/ItsAlphaNeon/Lemon-Studio/blob/0af860dfd31c7ee9cbf8af6747617e031a1a7742/plugins/lemon-reverb/src/lib.rs#L84).

6. **Tempo and transport state affect sound.** Reverb and Delay receive host BPM; chorus uses reproducible starting phases; EQ has explicit reset/preroll behavior. Choose a project BPM/default and expose tempo sync only when its meaning is clear. Specify seek, loop wrap, stop/resume, auditioning a selection, and sample-rate changes. Offline bounce and live playback must use the same initialization/state rules, including processing preceding audio when needed for the same seek sound. [Delay tempo/reset](https://github.com/ItsAlphaNeon/Lemon-Studio/blob/0af860dfd31c7ee9cbf8af6747617e031a1a7742/plugins/lemon-delay/src/lib.rs#L93), [Reverb tempo/reset](https://github.com/ItsAlphaNeon/Lemon-Studio/blob/0af860dfd31c7ee9cbf8af6747617e031a1a7742/plugins/lemon-reverb/src/lib.rs#L101), [chorus phases](https://github.com/ItsAlphaNeon/Lemon-Studio/blob/0af860dfd31c7ee9cbf8af6747617e031a1a7742/crates/os-engine/src/effects/chorus.rs#L7), [EQ preroll](https://github.com/ItsAlphaNeon/Lemon-Studio/blob/0af860dfd31c7ee9cbf8af6747617e031a1a7742/crates/os-engine/src/effects/eq/equalizer.rs#L334).

7. **Routing features expand scope.** External compressor sidechain requires a signal source and routing rules, not just copying a numeric control. Stereo Shaper's difference output likewise requires extra routing and is deliberately absent from the standalone plugin UI. Proposed first version: regular self-detection in Limiter, no external sidechain or difference output; omit those controls until routing exists. [Limiter sidechain input](https://github.com/ItsAlphaNeon/Lemon-Studio/blob/0af860dfd31c7ee9cbf8af6747617e031a1a7742/plugins/lemon-limiter/src/lib.rs#L144), [Stereo Shaper omission](https://github.com/ItsAlphaNeon/Lemon-Studio/blob/0af860dfd31c7ee9cbf8af6747617e031a1a7742/plugins/lemon-small-fx/src/stereo_shaper.rs#L9).

8. **Parameter, undo and headless contracts should be native.** Give each instance a stable ID; share typed parameter metadata, ranges, units and validation across egui, headless and MCP. Commit a continuous knob drag as one undo step while streaming live values; do not serialize DSP delay lines or transient UI meter state as parameters. Store presets and chain order with the document. Avoid inheriting raw FL-state plus NIH parameter overlay complexity: the Reverb wrapper, for example, persists both raw bytes and parameters because it preserves source format details. [Reverb state/parameter architecture](https://github.com/ItsAlphaNeon/Lemon-Studio/blob/0af860dfd31c7ee9cbf8af6747617e031a1a7742/plugins/lemon-reverb/src/params.rs#L5). The proposed native contract follows the user's pre-alpha constraint.

9. **Same renderer, atomic linked bounce.** Use the same DSP adapter and parameter revision for live playback, lossless arrangement bounce, WAV/MP3 export, headless and MCP. On switch to multitrack, snapshot the document revision and stack, render off-thread, then update all linked clips together; reject stale completion if edits have advanced. Budget memory/CPU for many independent clip chains and open analysis windows. These are WaveBob design requirements inferred from the requested ownership model, not features established by this upstream review.

10. **Reuse fits the existing GPL direction; preserve provenance and notices.** Upstream declares `GPL-3.0-or-later` in its workspace manifest, and inspected DSP/editor files carry that SPDX header. WaveBob's README already declares GNU GPL v3 and its root LICENSE contains GPLv3, so this aligns with the project's current licensing direction; the missing Cargo license field does not mean WaveBob is unlicensed. When incorporating code/UI, retain copyright and license notices, record the pinned origin and modifications, and include the corresponding source and dependency notices required for distribution. Audit the selected helper dependencies as part of extraction rather than importing unrelated plugin/SDK machinery. [Workspace license](https://github.com/ItsAlphaNeon/Lemon-Studio/blob/0af860dfd31c7ee9cbf8af6747617e031a1a7742/Cargo.toml#L6), [DSP header example](https://github.com/ItsAlphaNeon/Lemon-Studio/blob/0af860dfd31c7ee9cbf8af6747617e031a1a7742/crates/os-engine/src/effects/reverb.rs#L1), [upstream license sections 5–6](https://github.com/ItsAlphaNeon/Lemon-Studio/blob/0af860dfd31c7ee9cbf8af6747617e031a1a7742/LICENSE), [WaveBob licensing declaration](../../README.md#license), [WaveBob license](../../LICENSE).

## Verification needed during implementation

Pin the source revision and establish reference renders before adaptations. Test live/offline agreement at multiple sample rates and buffer sizes; silent input and extreme allowed values; bypass, reorder and removal during playback; EQ/limiter latency changes; reverb-size gestures; mono/stereo round trips; bounded tail termination; seeks and loop boundaries; undo while windows remain open; and callback allocation/CPU behavior under multiple chains. Keep gain/fade edits separate from effect controls, and test that document processing is baked only once when linked clips switch to the new bounce.

The upstream repository contains unit tests and an optional effect null-test harness, but that harness requires external case/reference files and documents exclusions such as mixer behavior. Its presence is not evidence that all sonic equivalence checks have been run or that WaveBob integration is validated. [Null-test harness and requirements](https://github.com/ItsAlphaNeon/Lemon-Studio/blob/0af860dfd31c7ee9cbf8af6747617e031a1a7742/crates/os-engine/tests/fx_null.rs#L5). This review ran no upstream or WaveBob DSP tests.

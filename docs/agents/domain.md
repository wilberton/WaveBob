# Domain docs

This project uses a single-context domain layout: `GLOSSARY.md` at the repository
root and architecture decisions under `docs/adr/`.

Before exploring a domain change, read the glossary and relevant ADRs when they
exist. If absent, proceed without scaffolding empty files. Use the glossary's
terms consistently; until it exists, use the domain definitions in the canonical
WaveBob spec. Add domain documentation when terms or decisions are resolved.

When proposing a change that conflicts with an ADR, identify the conflict and
explain why the decision should be reopened rather than silently overriding it.
